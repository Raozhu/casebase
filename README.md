# casebase

casebase 是一个常驻在 macOS 刘海区的轻量知识入库工具。

它解决的问题很直接：当你在工作里不断遇到截图、文件、票据、证件、网页文字、临时资料时，这些内容通常会散落在桌面、下载目录、剪贴板和聊天窗口里，后续很难再找到，也很难真正拿来回答问题。casebase 把这些临时内容变成可保存、可追问、可回看的个人资料库。

## 它适合谁

- 需要频繁处理截图、文件、文本、证件、票据等临时资料的人
- 想把“看过一次就忘”的资料快速沉淀为可检索知识的人
- 希望尽量少打断当前工作流，不想切换到重型知识管理工具的人

## 你可以用它做什么

- 拖入文件、图片、PDF、文字或音频，快速入库
- 使用快捷键直接把选中文字或截图送入资料库
- 对内容做 AI 识别、摘要和结构化整理
- 当资料信息不足时，让 AI 用最少的问题向你补全关键缺口
- 在“已存数据”里查看已保存内容和详情
- 基于已保存资料继续提问并获得回答
- 在中文和英文界面之间切换

## 产品特点

### 1. 始终在手边

casebase 以刘海区悬浮层的形式存在，不占用 Dock，不需要单独打开主窗口。鼠标悬浮即可展开，离开即可收起。

### 2. 导入方式快

你可以用三种方式把内容送入 casebase：

- 直接拖入文件、图片、PDF、音频或文字
- `⌘F1` 读取当前选中文字并入库
- `⌘F2` 启动截图并将截图内容入库

### 3. 不完整内容也能继续处理

当 AI 判断资料关键信息不足时，casebase 不会直接失败，而是进入“待补全”：

- 告诉你哪里不确定
- 给出几个可直接选择的补全选项
- 支持手动输入答案
- 确认后立即继续分析并完成入库

### 4. 已存数据可回看、可追问

每条入库内容都会保留整理结果、摘要和详情。你可以：

- 在“已存数据”里浏览和查看详情
- 基于已保存资料继续提问
- 对失败或待补全任务继续处理

## 怎么使用

### 快速开始

1. 启动 `casebase.app`
2. 第一次使用时按需要授予权限
3. 用拖拽或快捷键把内容送入 casebase
4. 等待入库完成，或在需要时补全关键问题
5. 在“已存数据”中查看结果，或直接继续提问

### 日常操作

- 鼠标悬浮到刘海区：展开主操作面板
- 拖动内容到刘海区：释放后自动收起并在后台入库
- 点击任务队列：查看当前处理状态、失败项或待补全项
- 点击已存数据：浏览资料库和详情
- 打开设置：修改快捷键、清空数据、重启或退出应用

## 权限说明

casebase 会按功能请求权限，不会无条件索取。

- 辅助功能：用于读取当前选中文字
- 屏幕录制：用于截图入库

如果权限未授予，对应快捷功能不会触发。

## 快捷键

默认快捷键如下：

- `⌘F1`：文字入库
- `⌘F2`：截图入库

你可以在设置页里修改快捷键，也可以恢复默认值。

## 数据与状态

入库过程中你会看到几种典型状态：

- 入库中：内容正在识别和写入资料库
- 待补全：信息缺口较大，需要你补一个关键答案
- 失败：导入或分析失败，可查看原因并重试
- 已完成：内容已保存，可进入详情查看

## 本地数据

casebase 会把资料保存到本地资料库中，便于后续回看和问答。设置页提供：

- 清空数据
- 重启应用
- 退出应用

## 当前交互风格

casebase 追求的是“尽量少打断”的使用方式：

- 能拖就拖
- 能选就选
- 能补一个答案就不要求你重新整理整份资料
- 能收起就收起，把等待和处理放到后台

## 开发运行

如果你是开发者，可以直接打开 `casebase.xcodeproj` 运行 `casebase` target。

## 本地只读 MCP Companion

`casebase` 现在附带一个本机运行的只读 `stdio` MCP companion：`casebase-mcp`。

它只暴露本地资料库里的元信息和真实文件绝对路径，例如：

- 数据列表
- 本地搜索结果
- 标签、用途、场景、摘要
- 每条记录对应的本地绝对路径

它不会上传文件，不会通过 MCP 传输文件内容，也不会使用远端服务器。

### v1 能做什么

当前只提供 3 个只读 tools：

- `casebase_list_records`
- `casebase_search_records`
- `casebase_get_record`

返回结果只包含元数据和本地路径，不返回文件字节内容，也不返回 embedding。

### 启动方式

打包后的推荐命令路径：

- GUI app: `/Users/rao/data/ai/casebase/dist/casebase.app`
- MCP executable: `/Users/rao/data/ai/casebase/dist/casebase-mcp`

`casebase-mcp` 通过 `stdio` 提供服务，适合配置到支持 MCP stdio 的 AI 客户端中。

示例：

```json
{
  "mcpServers": {
    "casebase": {
      "command": "/Users/rao/data/ai/casebase/dist/casebase-mcp",
      "env": {
        "CASEBASE_STORAGE_ROOT": "/Users/you/Library/Application Support/casebase"
      }
    }
  }
}
```

### 环境变量

- `CASEBASE_STORAGE_ROOT`
  用于覆盖默认资料库目录。未设置时默认读取 `~/Library/Application Support/casebase`
- `CASEBASE_API_KEY`
  `casebase-mcp` v1 不要求这个变量；浏览本地资料不应被 AI 配置阻塞

### 架构说明

- v1 完全不使用远端服务器
- 不会改动你服务器上的现有项目
- 其他 AI 工具必须和 `casebase` 数据运行在同一台 Mac 上
- 如果客户端不在这台 Mac 上，即使拿到本地路径也无法直接读取文件；这是架构限制，不是 bug
